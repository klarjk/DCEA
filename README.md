# DCEA — 커피 추출 진단 스킬

**D**ecent **C**offee **E**xtraction **A**ssistant

*[English](en/README.md)*

추출 변수와 맛본 느낌을 알려주면, 무엇이 원인인지 가려내고 **다음 잔에서 바꿀 변수 하나**를 알려주는 Claude 스킬입니다.

진단의 근거는 한 명의 홈카페 실험자(블로그 [klar201](https://blog.naver.com/klar201))가 수년간 정리한 추출 이론입니다. **일반적인 커피 상식과 어긋나는 항목이 여럿 있고, 충돌할 때는 이 스킬의 이론을 따릅니다.** 대신 어긋난다는 사실을 답변에서 밝힙니다.

---

## 무엇을 하나

- **관능 → 원인 감별** — 떫음·풋내·찌르는 신맛·밍밍함·쓴맛을 각각 다른 원인으로 나눕니다. 특히 떫음(유속의 순간 최대값)과 풋내(평균 유량)를 뭉뚱그리지 않습니다.
- **한 번에 한 변수** — 처방은 온도·유량·추출비·분쇄도 네 가지에서만 나가고, 한 번에 하나만 바꿉니다. 무엇이 효과였는지 알 수 있어야 하기 때문입니다.
- **향미 총량 판정** — 원두에 남은 향미의 총량을 먼저 가늠하고 방향을 정합니다. 향미가 부족하다고 해서 "더 뽑아내는" 방향(유량↑·시간↑·분쇄 가늘게)으로 처방하지 않습니다.
- **가진 도구 안에서** — 기본 모드에서는 알려주신 기구로 할 수 있는 조작만 처방합니다.

지원 기구는 에스프레소, 원뿔 드리퍼(V60 등), 평저형 드리퍼입니다. 원두 선택·로스팅 프로파일·머신 정비·모카포트는 범위 밖입니다.

## 실행 모드

호출할 때 인자로 고릅니다. 안 고르면 기본 모드입니다.

| 인자 | 도구 제한 | 답변 |
|---|---|---|
| (없음) | 가진 도구 + 저렴한 도구만 | 처방만, 짧게 (150단어 이내) |
| `barista` | 없음 | 처방 + 조작 세부·차선책·부작용 신호 (300단어 이내) |
| `geek` | 없음 | 위 전부 + 메커니즘·이론 근거·출처 번호 |

모드는 **답변의 범위만** 바꿉니다. 진단 논리는 세 모드가 같습니다.

## 설치

어디서 쓰시든 **레포 주소 하나로 시작합니다.** Claude Code에서는 Claude가 설치까지 끝내 주고, 채팅에서는 압축 파일까지 만들어 줍니다 — 등록만 손으로 하시면 됩니다.

### Claude에게 시키기 — Claude Code (터미널 · 데스크톱 앱 Code 탭 · IDE 확장)

세 군데 모두 같은 방식입니다. Claude에게 이렇게 말하면 알아서 받아 설치합니다.

```
https://github.com/klarjk/DCEA 를 ~/.claude/skills/dcea 에 설치해줘
```

영문판을 쓰시려면 부탁을 한 줄만 바꿉니다.

```
https://github.com/klarjk/DCEA 를 받아서 en/ 폴더를 ~/.claude/skills/dcea 로 연결해줘
```

손수 하시려면 이렇습니다.

```bash
# 한글판
git clone https://github.com/klarjk/DCEA.git ~/.claude/skills/dcea

# 영문판
git clone https://github.com/klarjk/DCEA.git ~/DCEA
ln -s ~/DCEA/en ~/.claude/skills/dcea
```

재시작 없이 바로 인식됩니다. `/dcea`로 확인하세요.

### 채팅에서 쓰기 — 데스크톱 앱 Chat 탭 · claude.ai 웹 · 모바일

채팅 쪽은 Claude가 스킬을 대신 등록해 주지는 못합니다. 압축 파일을 만들어 주는 데까지가 한계이고, 올리는 건 직접 하셔야 합니다. 대신 **한 번 올리면 계정에 저장되어** 세 곳 어디서나 쓰입니다. 모바일에는 올리는 화면이 따로 없으니 데스크톱이나 웹에서 등록하세요.

1. **설정 → Capabilities에서 코드 실행(code execution)을 켭니다.** 꺼져 있으면 스킬 항목 자체가 보이지 않습니다.
2. 압축 파일을 준비합니다. Claude에게 이렇게 부탁하면 레포를 받아 압축하고 내려받을 링크를 줍니다.

   ```
   https://github.com/klarjk/DCEA 를 받아서 dcea 폴더 하나가 최상위에 오도록 압축하고 내려받을 링크를 줘
   ```

   영문판은 `en/` 폴더 내용으로 만들어 달라고 덧붙이시면 됩니다. [릴리스 페이지](https://github.com/klarjk/DCEA/releases/latest)에서 바로 받아도 같습니다 — 한글판은 `dcea.zip`, 영문판은 `dcea-en.zip`.
3. 받은 파일을 사이드바 **Customize → Skills → + → Upload a skill**로 올리고, 목록에서 켜면 끝입니다.

<details>
<summary>직접 압축하고 싶다면</summary>

압축 파일 안에는 스킬 폴더 하나가 최상위에 있어야 합니다. 파일들이 최상위에 흩어져 있으면 업로드가 거부됩니다.

```bash
git clone https://github.com/klarjk/DCEA.git dcea-src

# 한글판
mkdir -p build/dcea && cp -R dcea-src/SKILL.md dcea-src/references dcea-src/sources build/dcea/
cd build && zip -r ../dcea.zip dcea && cd ..

# 영문판
mkdir -p build-en/dcea && cp -R dcea-src/en/SKILL.md dcea-src/en/references dcea-src/en/sources build-en/dcea/
cd build-en && zip -r ../dcea-en.zip dcea && cd ..
```
</details>

### ChatGPT 등 다른 AI

스킬을 등록해 두는 기능이 없으니, 대화를 시작할 때마다 압축 파일을 첨부하는 방식입니다.

1. [릴리스 페이지](https://github.com/klarjk/DCEA/releases/latest)에서 압축 파일을 받습니다. 페이지 아래 **Assets** 목록을 펼치면 한글판 `dcea.zip`과 영문판 `dcea-en.zip`이 있습니다.
2. **압축은 풀지 않습니다.** 받은 `.zip` 파일을 그대로 대화창에 끌어다 놓거나 클립 모양 첨부 버튼으로 올립니다. 압축 파일을 열어 읽을 수 있는 도구여야 하니, 파일 업로드와 코드 실행을 지원하는 플랜인지 확인하세요.
3. 첨부한 뒤 이렇게 부탁합니다.

   ```
   첨부한 압축 파일을 풀고 SKILL.md의 절차대로 내 추출을 진단해줘.
   참조가 필요하면 references/ 폴더의 파일을 읽어줘.
   ```

4. 새 대화를 열 때마다 1~3을 되풀이해야 합니다. 스킬처럼 계정에 남지 않습니다.

압축 파일을 못 다루는 도구라면 `SKILL.md` 하나만 열어 내용을 통째로 붙여넣어도 기본 진단은 나갑니다. 다만 `references/`의 진단표와 변수 사전을 못 보므로 처방이 거칠어집니다.

어느 쪽이든 파일을 읽어 절차를 따르는 것이므로 결과는 Claude보다 들쭉날쭉할 수 있습니다.

## 쓰는 법

Claude Code에서는 `/dcea`, 채팅에서는 그냥 증상을 말하면 스킬이 붙습니다.

```
/dcea 오늘 샷이 떫게 나왔어
에스프레소가 너무 써
V60이 보리차 같아, 바리스타 모드로 봐줘
/dcea geek 왜 푸어 횟수를 늘리라는 거야?
```

빠진 정보는 되물으니 아는 만큼만 말해도 됩니다. 다만 아래 네 가지가 있으면 되묻는 과정 없이 바로 진단이 나갑니다.

1. **기구** — 에스프레소 / 원뿔 드리퍼 / 평저형 드리퍼, 그리고 바스켓·드리퍼 모델
2. **도징량 · 추출량 · 추출시간** — 추출량은 부은 물이 아니라 **컵에 담긴 무게**입니다
3. **맛본 느낌** — 쓴가, 신가, 떫은가, 밍밍한가. 식으면서 어떻게 변하는지도 단서가 됩니다
4. **원두** — 배전도, 로스팅 날짜

굴절계(TDS 측정기)는 없어도 됩니다. 묻지 않습니다.

### 기록

Claude Code에서는 장비·기준선·진단 이력이 `~/.claude/dcea/profile.md`에 쌓입니다. 같은 처방이 두 번 효과를 보면 그 값이 기준선으로 올라가고, 그 뒤로는 **저자의 수치보다 사용자의 실측값이 우선**합니다. 채팅이나 다른 AI에서는 대화가 끝나면 사라지니, 장비와 평소 세팅을 앞부분에 한 줄로 적어 주시면 됩니다.

## 알아 두실 것

- **모든 수치는 저자 장비 기준입니다** (Lagom P64 + SSP cast, Decent XL, V60). 그래서 처방은 절대값이 아니라 "지난번보다 어느 쪽으로"로 나갑니다. 그라인더와 머신이 다르면 최적값도 다릅니다.
- **확신도가 함께 표기됩니다** — `[검증]` 직접 실험 / `[경험]` 경험적 관찰 / `[이론]` 물리적 유도 / `[가설]` 저자 추정. 가설에 근거한 처방은 가설이라고 밝히고 확인할 방법을 함께 냅니다.
- **저자가 모른다고 밝힌 영역은 모른다고 답합니다.** 지어내지 않습니다.

## 저장소 구조

| 경로 | 내용 |
|---|---|
| `SKILL.md` | 진단 절차와 답변 형식 |
| `references/` | 이론·진단표·변수 사전·레시피·기구별 메커니즘 |
| `sources/blog/` | 근거가 된 블로그 원문 |
| `en/` | 위 전부의 영어판 |
